## What it is
A fork of gufo-org/gufo specializing in Linux x86-64 Strix Halo gfx1151 and XDNA2 NPU operation. Its current headline is Qwen3.8 Flash-Next UD-IQ4_XS with a shared Q8 MTP sidecar, not the dense27B Q6 or Q4/DFlash configuration already used here. The installed Windows fork is pixmaate/gufo windows-2026-10-03, source2eb0778ac15d9e1c18c5b2f9e5dbbecc19e20ec2; these are distinct projects/builds. [Repository](https://github.com/mikealanni/gufo), [performance target](https://github.com/mikealanni/gufo/blob/dfb5f578eec1f25fc49d6516225a5229f29a90c8/docs/PERFORMANCE.md).

## Why it is interesting
Owner reports GPU-only/GPU+NPU prefill1837/2013tok/s at8K,1821/1963 at16K,1788/1949 at32K, and served42K cold prefill1836tok/s. Small synthetic runs include repetition count2; text mix affects expert routing and speed. Headline decode approximately50tok/s at116K and76tok/s on HumanEval are claims, not independently reproduced here or universal rates. NPU work overlaps selected projection/shared-expert GEMMs with GPU work; it is primarily a prefill improvement, not all-model NPU generation. [README](https://github.com/mikealanni/gufo/blob/dfb5f578eec1f25fc49d6516225a5229f29a90c8/README.md).

## Material limitations
The author documents machine hangs when fabric clocks change while NPU work is active. The NPU path requires holding fabric clock at the top level, balanced/performance NPU mode (not turbo), preventing NPU runtime suspend, and XRT/NPU support. It is not a normal install-and-forget runtime. The launcher checks clock state and turbo mode and otherwise falls back to GPU-only, but no independent hardware-safety validation was performed. At16K prefill tiles, documented scratch is approximately9GiB versus3GiB at8K. [NPU guide](https://github.com/mikealanni/gufo/blob/dfb5f578eec1f25fc49d6516225a5229f29a90c8/docs/NPU.md).

The fork's own quality notes say final partial-group NPU work changes7of30 greedy completions against the previous build, starting with an empty/text first-token flip; similar prompt sensitivity exists in its GPU baseline. This does not establish7/30 incorrect answers, but it rules out calling this path output-identical. Older benchmark/quality tables describe UD-Q4_K_XL and an October10 build, while today's README advertises UD-IQ4_XS. Their results must not be merged into one fully validated current configuration. The inherited reference MTP comparison also carries an explicit qualification caveat. [Quality](https://github.com/mikealanni/gufo/blob/dfb5f578eec1f25fc49d6516225a5229f29a90c8/docs/models/qwen3.8-flash-next/QUALITY.md), [benchmarks](https://github.com/mikealanni/gufo/blob/dfb5f578eec1f25fc49d6516225a5229f29a90c8/docs/models/qwen3.8-flash-next/BENCHMARKS.md).

## DSH and memory fit
The server documents Chat Completions/Responses/Messages APIs with tools, caching and namespaced usage.gufo timing. DSH provider integration is plausible, not exercised. Its launcher serves a Flash-Next GGUF plus optional MTP sidecar at port8900, context131072 and a16384-token output cap, with RAM/disk snapshot caches. Those are script defaults, not this machine's settings. A128GB Halo is the documented benchmark hardware, but existing64/64 Windows allocation is not proof this larger model fits the desired Linux memory layout. Full weight, KV, scratch, NPU and OS headroom must be accounted for. [Server](https://github.com/mikealanni/gufo/blob/dfb5f578eec1f25fc49d6516225a5229f29a90c8/docs/SERVER.md), [launcher](https://github.com/mikealanni/gufo/blob/dfb5f578eec1f25fc49d6516225a5229f29a90c8/scripts/run-gufo.sh).

## Judgment
Useful as a second candidate for a dedicated Linux Halo research environment, particularly Flash-Next GGUF/MTP and GPU/NPU cooperation. Hipfire is the broader first candidate from this pair; this fork is the more specialized Flash-Next/NPU experiment. That is a judgment about documented scope and setup constraints, not a measured speed/quality ranking. Nothing establishes it as faster than Hipfire or a direct upgrade to the installed Windows27B Gufo workload. No purchase, installation or replacement is recommended on these claims alone.
