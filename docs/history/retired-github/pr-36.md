## Original description

Fixes #35 — found live on the 5070ti box, where a conversion deploy put HALO's `AGENTS.md` into `~\Desktop\Code` and a running Codex session read it as its own operating instructions.

## What changed

**1. `files:` in the machine-profile format.** Line-replacements are the wrong tool for prose — there is no stable `find` string in `AGENTS.md`, and a missed one ships another machine's *instructions*, not just a wrong value. A `files:` entry swaps the deployed file outright.

The rot guard is a hash rather than a find-string: `baseSha256` pins the master file the machine copy was derived from. A whole-file swap means the port box stops inheriting base improvements to that file, so if master's version moves the deploy **fails** and prints both hashes. Same silent-rot protection find-must-exist gives replacements. A file may be swapped or line-replaced, never both — the deploy rejects a profile that does both.

**2. A scope gate on every deployed `AGENTS.md`, every machine including HALO.** It must carry a `SCOPE:` line in its first ten lines. The gate reads the *rendered* bytes, so it inspects exactly what lands live. On HALO the header is harmless; on a shared box it is the difference between a config file and a prompt injection into unrelated agents.

**3. `DEPLOY_DRYRUN=1`.** Renders and gates another machine's profile from HALO and stops before touching anything, leaving the rendered copy in `%TEMP%` for inspection. Previously the only way to test `MACHINE=5070ti` was to deploy 5070Ti config onto the live box — which is why that profile shipped unvalidated, and why this bug was found by a contaminated session instead of by a test.

## The 5070ti AGENTS.md

Authored from **current master**, not the copy on `tester/5070ti` — that branch predates the fleet-origin, output-wall and memory-graph sections.
