## Original description

Workflow design (spec.json is the source; design doc, mermaid, and HTML rendered from it) for running arbitrarily large generative work on the stack without ever hitting the output-token wall. Built from code-level research of the installed dsh packages, not assumptions. Key traced facts the design rests on: (1) the harness never auto-continues a max-tokens turn and the autonomous goal driver explicitly DISARMS on it; (2) truncated tool calls are silently discarded - unrecoverable by design; (3) max_tokens is never clamped to remaining context room client-side - the server cuts the stream; (4) cordis_define is schema-locked to whole-source emission (additionalProperties:false, no diff field); (5) the apiproxy sessions endpoint exposes contextPressure {contextWindow, projectedTokens} - live room is measurable by an orchestrator today; (6) dsh ships an incremental file-write path (create/insert/str_replace). The pipeline: measure room deterministically, plan chunks capped at min(0.5*room, 12K), emit via incremental file tools, hard-fail any max-tokens turn, retry ONLY in fresh context, integrate, frontier review, PR, one human gate at merge.
