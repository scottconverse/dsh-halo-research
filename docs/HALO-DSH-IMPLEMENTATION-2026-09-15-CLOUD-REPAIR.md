# Cloud provider repairs — September 15, 2026

## What failed

The active research conversation established three distinct failures, not missing cloud accounts:

- `xai-oauth/grok-4.20-0309-non-reasoning`: xAI rejected `reasoningEffort`. The community plugin inferred reasoning metadata from a different Grok model.
- `google/deep-research-max-preview-04-2026`: Google rejected normal chat requests because this agent requires the separate Interactions API. It should not have been offered by this chat adapter. Google documents the separate interface at https://ai.google.dev/gemini-api/docs/deep-research.
- `deepseek-official/deepseek-flash`: no direct DeepSeek API credential exists on this installation.

A subsequent real DSH check also found `google/gemini-3.8-flash` rejected the adapter's implicit `MINIMAL` thinking setting.

## Changes

- The stock Cordis `llm-deepseek` row is disabled in `stack/stock-dsh/cordis.patch.yml` and the live home overlay. This removes the direct DeepSeek route from the composer without affecting Ollama's DeepSeek route. Re-enable the row if a direct DeepSeek API key is added later.
- Google uses the stock `llm-pi-ai.providers.google.models` allowlist, preserving the existing catalog except its two Interactions-only Deep Research entries. No Google model or account was deleted. Restoring the full upstream catalog means removing this `models` list, but it would reintroduce those incompatible entries.
- Gemini 3.8 declares Low, Medium and High reasoning choices, excluding unsupported Minimal. The Google route now explicitly defaults to High, which avoids the transport's implicit Minimal fallback and is supported across its declared reasoning models. Users can select another offered effort. High can take longer than the previous implicit setting. Other Google catalog entries are retained, not blanket-certified as entitled or tested.
- The pinned `dsh-xai@0.1.0` pnpm patch now recognizes explicit non-reasoning model IDs, clears inherited thinking metadata, and leaves other model descriptors unchanged. Its previous DSH alpha adapter/image-budget fixes are retained. Both shipped TypeScript and bundled JavaScript are patched. No stock DSH source changes.
- The web-profile lockfile was regenerated by pnpm and the live profile installed with `--frozen-lockfile --ignore-scripts`. DSH was restarted only after the user's research session was idle. LM Studio and its resident models were left running. Saved session histories and the user's selected Ollama default were preserved.

## Verification

Bounded DSH sessions ask the model to read a fresh file containing a random value that is absent from the prompt, then return its contents. Acceptance requires the real read tool call, successful result, matching content, the expected provider/model attribution, and a completed turn. This checks a round trip through the provider with tools and tool-result replay, beyond a no-tools greeting. It does not certify every model, image/video generation, or long research tasks.

See `docs/evidence/cloud-provider-repair-2026-09-15.json` for individual sessions, failures, repaired results and the final picker catalog. Gemini 3.6 used the lean coding preset. Repaired Gemini 3.8, Grok 4.20 non-reasoning, Grok 4.6 and Ollama DeepSeek used the full Local models preset. Ollama may wrap the correct value in a Markdown code block; formatting is recorded separately from provider/tool success.

The dependency-free regression at `stack/stock-dsh/web-profile/test/xai-non-reasoning-bundled.mjs` imports the actual installed plugin bundle and checks non-reasoning IDs, the reasoning sibling, boundary matching, and preservation of exact catalog descriptors. It passed against the installed patched bundle.
