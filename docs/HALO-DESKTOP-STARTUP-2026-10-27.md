# DSH Desktop startup repair - October 27, 2026

## Outcome

The normal DSH Halo Desktop shortcut now opens a responding DeepSeek Harness window. A failed model-catalog refresh uses the saved catalog instead of preventing startup. The existing selected-model safety check remains mandatory. Refresh and safety-check output, including exceptions, is retained in the Desktop home's `logs/desktop-startup.log`.

## What failed and what remains uncertain

Scott's screenshot showed the launcher's catalog-refresh failure dialog. Source inspection confirmed that any nonzero refresh exit prevented Desktop from opening, despite the dialog saying its saved catalog was retained. The launcher hid the refresh output and saved no diagnostic log, so the specific exception from that earlier click cannot be recovered from this evidence.

The unmodified refresh succeeded under normal Windows access against a disposable profile: 14 LM Studio chat models and 25 Ollama tags were discovered. This establishes recovery at inspection time, not a diagnosis of the earlier refresh failure. The restricted-shell probe initially waited on the LM Studio CLI, then returned its existing inventory-unavailable warning; Windows Script Host was also denied in the restricted context. The focused checks were therefore run with normal authorized Windows access. Those restrictions are not evidence of a broken LM Studio installation.

## Change

`stack/desktop-tuning/Launch-DeepSeek-Harness-Evaluation.vbs` is now the recorded source for the installed Desktop launcher. Catalog discovery is optional; selected-route validation is not. The launcher records refresh failures and proceeds to the existing safety helper. A failed safety helper still stops startup and names the diagnostic log. The refresh generator, safety helper, application binary and model policy were not modified.

## Verification actually performed

- One disposable-profile refresh reproduced the current successful discovery behavior without changing the live profile.
- Two small offline launcher fixtures exercised the changed control flow: forced refresh failure plus successful safety check reached the application-launch boundary (exit 0); forced safety failure still blocked launch (exit 1). The fixtures did not open an app or call a model.
- After deployment, the normal Desktop shortcut was opened. Its log records successful refresh, the saved Ollama cloud route, unchanged model residency and a successful safety check at 12:27:36 PM Mountain. Windows reported a responding DeepSeek Harness main window, PID 48784 at observation time; this is historical process evidence, not a reusable PID.
- The live profile diff contains catalog array-spacing normalization only. Model IDs, defaults, effort, limits, plugins and integrations were preserved. The saved default remains `ollama / deepseek-v4.1-flash:1017-cloud`, Low effort. No inference, benchmarks, subagents or broad test suites were used.
- All three desktop shortcuts were inspected as one maintenance set: DSH Halo Desktop, Start DSH Web, and Stop DSH + Wigolo. Their executable targets and icon files exist, and Web Start/Stop still point at their separate current scripts. Web was neither started nor stopped for this repair.

## Limits and recovery

This fixes the confirmed fatal-refresh startup path; it does not prove what caused the earlier refresh exception or that every DSH tool works. The optional refresh still runs synchronously; this change does not add a timeout to the LM Studio CLI. The new diagnostic log is local and is not published. Private rollback copies of the old launcher and profile are retained in the dated Codex task folder. No model files, credentials, raw conversations or backups belong in this commit.

Scott explicitly requested a standing rule: maintain the Desktop app shortcut and both Web Start/Stop shortcuts together whenever launcher/icon updates are made. That rule is saved in the repository and in the requested Codex memory update note. The three distinct actions must be preserved.

## Accounting

No model jobs or provider tokens were generated by verification, and no subagents were used. Exact coordinator input/output/cached token accounting is not exposed by the tools available in this turn; it is unavailable, not zero. Avoided additional model jobs and unrelated runtime tests.
