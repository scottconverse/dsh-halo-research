5. Suggested replacement text

Use or adapt the following language; keep the report’s existing tone and
evidence discipline.

5.1 Clean-room declaration

  This investigation’s architecture and primary findings were derived
  from first principles without relying on the prior HALO-stack
  implementation. After the clean-room baseline was complete, selected
  earlier first-party evidence from this same machine was reviewed and
  incorporated where explicitly identified, including §12.8. No prior
  implementation architecture or code was inherited into the recommended
  design. Addendum and later-revision material is identified in place
  and sourced according to the report’s evidence hierarchy.

5.2 PyTorch status

  PyTorch on native Windows for gfx1151: vendor-documented supported;
  AMD publishes torch[device-gfx1151]==2.12.0+rocm7.14.0. It was not
  installed or executed during the clean-room test, so T-18 remains the
  machine-level verification step. vLLM/SGLang and broader
  training-stack support remain unestablished unless separately
  verified.

5.3 Vulkan decision summary

  Vulkan remains the default. ROCm has a large, reproducible prefill
  advantage at short-to-moderate context, but its GPU-memory footprint
  is materially larger at ordinary 32K workloads and grows with prompt
  size, while Vulkan remains flat. ROCm decode is also less consistent
  and is decisively slower from 32K upward in the replicated
  measurements. The confounded 45K long-context parity result is
  retained only as an observation and is not used to justify the
  decision.

5.4 Earlier deployment evidence

  An earlier rc.7/65K HALO deployment produced additional first-party
  measurements. Those results are not used as current-stack performance
  evidence because the deployment, context configuration, runtime state,
  and architecture were superseded before the clean-room investigation.
  Selected behavioral evidence from that period is incorporated only
  where explicitly identified, such as §12.8.

6. Findings and decisions that should be preserved

- DSH itself should remain almost entirely stock. Local LM Studio
  connectivity is configuration through dsh-llm-pi-ai, not a middleware
  engineering project.

- The plugin/package-count distinction is important: repository
  packages, CLI dependencies, and the composed web-profile package count
  are different numbers; retain the 133 mounted web-profile figure with
  its method.

- Native Windows is the intended execution path. Do not reopen
  Linux/WSL-primary as the default simply because ROCm exists there.

- Leave VGM at 64 GB for the default configuration. The report’s memory
  analysis correctly distinguishes firmware carve-out from GPU
  addressable memory and the max single-allocation limit.

- Keep Vulkan as the default llama.cpp backend and ROCm as an
  experimental lane. The decision is based primarily on memory shape and
  stability, not on a blanket claim that Vulkan is faster at everything.

- Keep Qwen3.8-27B UD-Q5_K_XL at 131,072 as the incumbent primary until
  a contender wins on measured agent tasks. The bartowski Q5_K_M test
  was a dead heat and provides no reason to switch.

- Keep the tools-on conclusion from §12.7: on the measured
  sandbox-favourable task set, tool access moved accuracy from 28% to
  100% and reduced wall-clock 5.1×. Preserve the report’s limitations
  language.

- Keep §12.8 as informal first-party behavioral evidence, not a
  benchmark. It is valuable because it shows refusal to fabricate,
  evidence-updating after the file changed, semantic reasoning about the
  bug, and no-commit constraint adherence.

- Keep model stacking through multiple tool-subagent instances and
  shipped provider/model bindings; do not introduce a custom auto-router
  unless later evidence justifies it.

- Keep subscription OAuth as the preferred path for supported
  subscription-backed providers, with API-key auth retained where
  required.

- Keep FastFlowLM/NPU, DeepSeek-V4-Flash, Qwen3-Coder-Next, tuned ROCm,
  parallel serving, and similar items in experimental/watch lanes unless
  the report’s own acceptance tests promote them.

- Keep the user’s removal of the prescriptive danger-full-access
  paragraph from §18.2 and the rewrite of §18.2b as an optional
  command-guard capability. Do not reinsert “counterweight,” “removal is
  stronger,” or similar policy prose.
