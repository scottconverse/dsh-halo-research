DSH Web and Desktop at 8K

All six tasks per machine used real local inference. Each machine returned correct meeting fields, cited the correct source line, and produced patches that passed the four-case Python check on both hosts. Every extraction response wrapped its JSON in a Markdown fence and failed strict raw JSON parsing.

Direct llama.cpp replays at 32K

The longest prompt contained exactly 24,842 input tokens on all three machines. Every answer used 213 completion tokens. The 5070 Ti completed the request 1.88× as fast as the 5060 Ti and 6.66× as fast as Halo. Most of the elapsed-time difference came before the first answer token.

Method and limits

  • Model. LM Studio Community’s Qwen3.5-9B-Q4_K_M.gguf, 5,627,044,256 bytes, SHA-256 cd76ec205963b3b33350093e6904d9de16c4e666fd104e1f632d25c7f15f2a13. The benchmark used text input and no vision projector. Model artifact
  • Runtime. llama.cpp build 12532, commit 08c252e22, on all three Windows PCs. Halo used Vulkan on its Radeon 8060S integrated GPU. Both 16 GB Blackwell cards used CUDA 13.5. One server slot, thinking disabled, and GPU offload requested for all layers. Build
  • Direct measurements. Identical prompt text at 8,192 and 32,768 configured context, temperature zero, up to 256 output tokens. Prompt caching was disabled in the request. First-token time measures the first answer text received by the streaming client. Generation speed comes from engine decode timings. Some answers used different numbers of output tokens.
  • Harness measurements. DSH 0.2.2-rc.5 ran in headless isolated profiles with fixture-scoped tools and a local endpoint on each PC. The 5070 Ti ran the matching Web CLI from the portable Desktop bundle through Electron in Node mode. The 5060 Ti ran the Web CLI under standalone Node. One measured successful attempt per task and host is reported. The initial Halo Desktop fixture rejected an extra built-in tool before inference and was rerun with that tool disabled in the fixture.
  • Scope. These measurements compare the tested hardware and backend combinations. They cover small bounded tasks and a single local request at a time. App startup, cold disk benchmarks, sustained multi-user service, and vision quality are outside the measurement. The publication reuses the saved benchmark and adds no inference runs.
